面试题 - HTTP相关

面试题 - HTTP相关

状态码分类

  • 1xx 服务器收到请求
  • 2xx请求成功
  • 3xx重定向
    • 301 永久重定向（更换域名等等）
    • 302 临时重定向 （临时更改，应用很多）
    • 304 资源未被修改 请求缓存
  • 4xx客户端错误
    • 403 没有权限
    • 404 资源未找到
  • 5xx服务端错误

请求类型

  • GET
  • POST
  • PUT
  • DELETE

RESTFUL语法

请求头的属性（不包括缓存相关）

  • Accept：浏览器可接受的数据格式
  • Accept-Encoding： 浏览器可接受的压缩算法，如gzip
  • Accept- Language：浏览器接受的语言
  • Connection：keep-alive 一次TCP连接重复利用
  • cookie
  • host
  • User-Agent：浏览器的信息
  • Content-type：发送数据的格式

返回头的属性

  • Content-type：返回数据的格式
  • Content-length：返回数据的大小
  • Content-Encoding：返回数据的压缩算法

HTTP 缓存

  • 什么是缓存？

缓存就是有些资源在一定时间内不会进行更改，加载一次后下次再次加载时就不必再去发起请求，而是调用以前加载的数据。

  • 哪些资源会被缓存？

静态资源（JS，CSS，img）

强制缓存

  • Reponse Header中

    • Cache-Control：控制强制缓存，单位是秒
      • max-age：最大过期时间
      • no-catch：不使用本地缓存，交给服务器处理
      • no-store：不使用本地缓存，也不使用服务端的缓存

协商缓存

  • 服务器缓存策略
  • 服务器判断客户端资源是否和服务端资源一致
  • 一致返回304 否则返回200和最新资源
  • 在 Response Headers 中，有两种
  • Last-Modified 资源的最后修改时间
  • Etag 资源的唯一标识（一个字符串，类似人类的指纹）
  • 会优先使用 Etag
  • Last-Modified 只能精确到秒级
  • 如果资源被重复生成，而内容不变，则 Etag 更精确

缓存的流程综述

三种浏览器的刷新操作

  • 正常操作：地址栏输入 url，跳转链接，前进后退等（强制缓存，协商缓存有效）
  • 手动刷新：F5，点击刷新按钮，右击菜单刷新 （强制缓存失效，协商缓存有效）
  • 强制刷新：ctrl + F5（不使用缓存）
