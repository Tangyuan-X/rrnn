第一章 概述

项目与日常活动的区别（能区分）

具有明确开始和结束时间（临时性），必须在规定的成本、质量和范围等限制条件下完成的一次性（独特性）事业，具有明确的目标。

1.1 项目管理

什么是项目，项目的基本特征

项目是一个特殊的将被完成的有限任务，它是在一定时间内，满足一系列特定目标的多项相关工作的总称。

目标性 相关性（关联性）临时性（一次性）独特性约束性（时限性） 不确定性 多方面性（一个项目涉及多个相关利益者） 不可逆转性

项目管理包含哪些内容 成功的项目管理具备哪些特征

项目管理就是将知识、技能、工具与技术应用于项目活动，以满足项目的要求。项目管理通过合理运用与整合特定项目所需的项目管理过程得以实现。管理一个项目通常包括（但不限于）：识别项目需求；处理相关方的各种需要、关注和期望；与相关方建立并维护积极的沟通；管理资源；平衡相互竞争的项目制约因素，包括（但不限于）：范围；：进度；：成本；质量；，资源；风险。

成功的因素

  1. 制定让划：预估和确定项目的工作量大小、所需资源和进度、风险应对措施等；
  2. 建立组织：建立项目组，并有明确的角色定义和任务分工；
  3. 配备资源：任用各种层次的技术人员和管理人员，以及准备所需的软硬件；
  4. 监控执行：协调项目各方人员，监控各种风险，督促项目进展，随吋检查实施情况，确保项目按计划进行， 按时、按质完成任务。
  5. 总结提高：项目完成后，及时进行总结，吸取教训， 分享经验，丰富组织的项目管理数据库或知识库。

软件项目管理的特殊性

  1. 软件项目是设计型项目
  2. 软件过程模型
  3. 需求变化频繁
  4. 难以估算工作量

  6. 以人为本的管理

1.4 敏捷项目管理

为什么要学习敏捷？传统生存期的不足之处？

  1. 各个阶段的划分完全固定，阶段之间产生大量的文档，极人地增加了工作量。
  2. 由于开发模型是线性的，用户只有等到整个过程的末期才能见到开发成果， 从而增加了开发风险。
  3. 通过过多的强制完成日期和甲程碑来跟踪各个项日阶段。
  4. 瀑布模型的突出缺点是不适应用户需求的变化。

敏捷项目的特征

  1. 迭代式开发 2. 增量交付 3. 开发团队和用户反馈推动产品开发 4. 持续集成 5. 开发团队的自我管理

常见的组织结构以及优缺点

职能型优点

可以充分发挥职能部门的资源集中优势部门的专家可以同时为部门内不同项目使用便于相互交流，相互支援

可以随时增派人员

可以将项目和本部门的职能工作融为一体

职能型缺点

项目和部门利益发生冲突，职能部门更重视本部门的目标,会忽视项目目标

资源平衡会出现问题

权利分割不利于各个职能部门的交流和团结协作

行政隶属关系使得项目经理没有充分的权利

项目型优点

项目经理对项目可以负全责

项目目标单一，可以以项目为中心，有利于项目顺利进行

避免多重领导

组织结构简单，交流简单,快速

项目型缺点

资源不能共享

各个独立的项目处于相对封闭状态，不利于公司政策的贯彻

对项目组织的成员缺少一种事业上的连续性和安全感

项目组织之间处于分割状态,缺少信息交流

矩阵型优点

专职的项目经理负责整个项目，以项目为中心

公司的多个项目可以共享各个职能部门的资源

既利于项目目标的实现,又利于公司目标方针的贯彻

项目成员的顾虑减少了

矩阵型缺点

容易引起职能经理和项目经理权力的冲突

资源共享也能引起项目之间的冲突

第三章 项目团队

什么是干系人，干系人根据项目的期望程度的分类，干系人对于项目的参与程度的分类？

干系人(stakeholder）是能影响项目决策、活动或者结果的个人、群体或者组织，以及会受到或者自认为会受到项目决策、活动或者结果影响的个人、 群体或者组织。

项目干系人参与分类

不知晓。对项目和潜在影响不知晓。

抵制。知晓项目和潜在影响，抵制变更。

中立。知晓项目，既不支持，也不反对。

支持。知晓项目和潜在影响，支持变更。

领导。知晓项目和潜在影响，积极致力于保证项目成功。

管理干系人期望

核心干系人：定期的全方位项目交流，包括项目组例会、与项目管理部门的沟通会议、项目关键里程碑会议总结等。

重要干系人：关键里程碑的前期评审会议，定期的项目状态和信息发布，定期收集反馈等。

非核心干系人：不定期，非正式的沟通是必要的。保持良好的合作关系。比如项目紧，需要加班，那么就需要行政部分提供加班餐和班车等服务。

沟通的有效性原则

原则之一：学会倾听 ，原则之二：表达准确 原则之三：及时沟通 原则之四：双向沟通 原则之五：换位思考

沟通的方式？如何选择合适的沟通方式？

方式：书面沟通和口头沟通 语言沟通和非语言沟通 正式沟通和非正式沟通 单向沟通和双向沟通 网络沟通

非技术专业人员更愿意非正式和双向会谈以听取重要的项目信息

沟通的有效性依赖于项目经理和项目组成员良好的沟通技

能口头沟通有助于在项目组成员和干系人之间建立较强联系

重大事件、项目变更、利益承诺、与合同有关的信息等要采用正式沟通（书面确认）

第七章 项目成本计划

什么是成本管理？ 包含哪些内容？

成本管理是确保项目在预算范围之内的管理过程，包括成本估算、成本预算、成本控制等过程。

什么是直接成本和间接成本？成本估算的基础和步骤是什么？

直接成本是进行项目成本估算的基础部分，也是最容易进行量化的部分，通常也构成项目成本的大部分金额，包括开发成本、管理成本、质量成本等。间接成本：培训房租水电 员工福利 市场费用 管理费 其他等等

输入：需求 资源计划 资源单价 进度计划 历史项目数据 学习曲线 。 处理：估算方法 输出：估算文件

影响软件项目成本的因素

项目质量工期 范围 管理水平 人力资源 价格

常见的估算方法？适合的场景？

代码行估算法：与具体的编程语言有关 分解足够详细 有一定的经验数据（类比和经验方法）

功能点估算法：主要适合信息系统，不适合实时系统或者嵌入式系统（外部特征不明显）

类比估算法：有类似的历史项目数据 信息不足（例如市场招标）的时候 要求不是非常精确估算的时候

自下而上估算 基于神经网络估算 专家估算

敏捷项目的快速故事估算法的过程？

团队成员排成一排；第一名成员将一个用户故事放到他认为可以正确反映故事点值的那一列；下一个成员可以挪动己经摆好的用户故事， 也可以选择另外的用户故事；继续以上过程，直至所有用户故事摆放完毕。

第十章 项目风险计划

风险的三要素？风险的性质？

风险三要素：事件、概率和影响。性质：不利性，可变性，相对性

风险管理的过程，如何更好识别风险？

软件项目风险管理包括风险识别、风险评估、风险规划和风险监控四个过程。

应采取主动的风险管理策略，即着力预防和消灭根源的管理策略。这一策略在项目计划阶段就启动了：识别出潜在的风险、评估它们出现的概率和潜在的影响、按照重要性进行排序，然后制定一个计划来管理风险。

风险应对有哪些策略？什么场合使用？

回避风险：对风险有足够的认识当风险发生概率极高，后果严重时采用当其他风险策略不理想的时候考虑采用避免某种风险的同时可能产生另外的风险有些风险是无法回避的

转移风险：也称通过采购转移风险，有意识将损失或与损失有关的财务后果转嫁出去的方法。 例如： 分包开脱责任合同保险

损失控制：损失预防损失抑制例如：项目技术培训，预防技术失败例如：项目人员储备，抑制人员流失的损失

自留风险：由项目组织自己承担风险事故所致损失的措施。 积极承担或消极承担

风险管理最佳实践？如何做好风险管理？

每个成员都参与其规划和防范过程中，并采取主动策咯，重点是预防风险设法消除或缓解那些后果严重白明确责任人不得不面对的风险，应集中精力制定对策来降低风险顾全大局

挣值分析

BAC：预算总值 TAC：预计完成时间 BCWS：计划工作成本 ACWP：实际工作成本 BCWP：已获值

BCWP（已获值）计算：50/50规则：开始，没结束 获得一半价值 0/100:未完成就没有价值。 经验加权：根据经验评估

进度差异SV = 实际工作成本BCWP - 计划工作成本BCWS

成本差异CV = 实际工作成本BCWP - 计划工作成本ACWP

CPI = （BCA - BCWP) / (Goal - ACWP)

十二章 项目结束过程

项目成功或失败的标准是什么？

是否有可交付的合格成果； 是否实现了项目目标； 是否达到项目客户的期望。

项目计划中确定的可交付成果已经出现， 项目的目标己经成功实现由于相关原因,项目无法继续进行,例如 ＞项目己经不具备实用价值 ＞项目无竞争力，难以生存

项目成功的要素？

项目必须通过正式验收； 必须进行认真的财务核算，客户的应付项目款要结清，项目组的开发实施费用要盘结清楚，保证利润、资金落实到位。 对项目的经验进行总结。 与客户保持良好的关系。

项目总结的意义？

分享经验。避免犯相同的错误 提出合理性建议 提升项目流程的改进 激励项目团队成员 积累最佳实践

项目总结的注意事项？如何开好项目总结会议？

一定要实事求是，成绩不能夸大，缺点也不能缩小，更不能弄虚作假。 分析问题着眼点要准确，分析要深入，不要回避、隐瞒问题和矛盾. 条理要清楚。有主次之分。条理不清的报告，谁都不愿意看，即使看了也不知其所以然，又怎么会给予支持和帮助呢？ 最好可以剪裁得体，图文并茂，去芜存精。对于一些分析结果以图表对比来呈现可以给人清新明了的感觉。
