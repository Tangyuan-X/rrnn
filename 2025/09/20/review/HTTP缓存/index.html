HTTP缓存浅析

强制缓存

Expires

默认没有缓存，想构建一个强制缓存，最简单的办法就是服务器添加响应头Expires（大小写无所谓）

这是1.0的缓存标准，严重依赖时间戳，若本地服务器时间不同步，或对客户端时间主动修改，都会使缓存不正确。

Cache control

使用chache control可以避免从客户端读时间，直接在服务端基础上滑动20s。

no-cache和no-store

是一对互斥的，不要同时设置

  • no-cache: 不进行强制缓存
  • no-store：不进行任何缓存

public和private

private：只允许浏览器缓存

public：允许代理和服务端缓存（设定过期时间 s-max-age）

协商缓存

使用本地之前发送一次GET请求，进行有效性验证。

last-modifined

请求头包含一个ifmodified-since字段，值是上次响应头中的last-modefined字段值。

一定要添加cache-control：no-cache，否则还是强制缓存。

缺点

  • 太依靠修改时间，修改时间不对则不对
  • 只能精确到秒

ETag

基于hash生成一个指纹，带到返回头Etag上

下次请求会携带一个if-none-match

Etag的不足：计算hash需要额外开销

为了增加性能，ETag也分强弱验证，弱验证计算速度快，但不保证每个字节都相同。

总结：流程图

HTML文档：协商缓存 （no-cache）

图片等静态资源：强缓存（cache-control + max-age）

style.css（指纹文件名 + max-age）
